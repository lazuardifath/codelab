Pemodelan Data Dasar — ERD

Menyusun gambaran data Sistem Akademik Universitas sebelum database dibuat.

0% · Belum dimulai

1. Mengapa perlu pemodelan data?

Sebelum membuat tabel, kita harus memahami objek apa yang disimpan dan bagaimana objek itu saling berhubungan.

Aturan bisnis: satu mahasiswa berada pada satu program studi. Mahasiswa dapat mengambil banyak mata kuliah dan satu mata kuliah dapat diambil banyak mahasiswa.

2. Entity

Entity adalah objek yang informasinya disimpan. Contohnya adalah Mahasiswa, Dosen, Program Studi, Mata Kuliah, dan KRS.

MAHASISWAobjek mahasiswa
MATA_KULIAHobjek mata kuliah
PROGRAM_STUDIobjek program studi
Kesalahan umum: Nama bukan entity. Nama adalah attribute dari Mahasiswa.

3. Attribute dan primary key

MAHASISWAPK nimnamaemailangkatan
  • Simple: email.
  • Composite: alamat.
  • Multivalued: nomor telepon.
  • Derived: usia dari tanggal lahir.
  • Key attribute: NIM sebagai identitas unik.

Primary key tidak harus berupa angka. Syaratnya unik dan tidak kosong.

4. Relationship

Relationship menjelaskan hubungan antarentity menggunakan kata kerja.

5. Cardinality

Cardinality menjawab pertanyaan “berapa banyak?” dari kedua arah.

1 : 1satu dengan satu
1 : Nsatu dengan banyak
M : Nbanyak dengan banyak
MAHASISWAM
mengambil
MATA KULIAHN

Relasi M:N akan membutuhkan entity penghubung KRS pada pemodelan logis.

7. Praktik terarah: membuat ERD dengan Visual Paradigm

Sekarang Anda tidak hanya membaca ERD. Anda akan membuat diagram sendiri menggunakan Visual Paradigm berdasarkan studi kasus Sistem Akademik Universitas.

Referensi screenshot langkah demi langkah
Tutorial resmi Visual Paradigm menampilkan gambar antarmuka untuk membuat project, entity, primary key, kolom, dan relationship. Gunakan sebagai referensi tampilan aplikasi, tetapi ikuti nama entity dan aturan bisnis Sistem Akademik pada latihan ini.

Ikuti tutorial di halaman ini. Visual di bawah adalah ilustrasi tampilan kerja Visual Paradigm yang disederhanakan. Nama menu dapat sedikit berbeda menurut versi aplikasi, tetapi urutan kerjanya sama.

Gambar 1 — Membuat project baru

Visual Paradigm — New Project
File   Project   Diagram   Tools   Help
New Project

Yang dilakukan: pilih Project → New, masukkan nama project, lalu pilih Create Blank Project.

Langkah 1 — Siapkan project

  1. Instal dan buka Visual Paradigm.
  2. Pilih New Project dan beri nama Sistem Akademik Universitas.
  3. Buat diagram baru melalui Diagram → New → Entity Relationship Diagram.
  4. Simpan project dengan nama sistem-akademik-er.

Langkah 2 — Buat entity

Tambahkan lima entity berikut ke canvas:

MAHASISWAPROGRAM_STUDIDOSENMATA_KULIAHKRS

Gunakan nama entity yang konsisten dan mudah dibaca. Jangan membuat entity bernama Nama atau Email; keduanya adalah attribute.

Gambar 4 — Membuat relationship

ERD Canvas

MAHASISWAPK nim

Yang dilakukan: pilih tool relationship, tarik dari entity pertama ke entity kedua, lalu beri nama relationship dan cardinality.

Langkah 4 — Hubungkan relationship

  1. Hubungkan PROGRAM_STUDI dengan MAHASISWA menggunakan kata kerja memiliki.
  2. Hubungkan MAHASISWA dengan KRS menggunakan kata kerja mengisi.
  3. Hubungkan KRS dengan MATA_KULIAH menggunakan kata kerja untuk.
  4. Hubungkan DOSEN dengan MATA_KULIAH menggunakan kata kerja mengampu.

Langkah 5 — Tentukan cardinality

Gunakan aturan bisnis berikut:
Satu program studi memiliki banyak mahasiswa, tetapi setiap mahasiswa berada pada satu program studi. Satu mahasiswa dapat memiliki banyak KRS. Satu mata kuliah dapat muncul pada banyak KRS. Satu dosen dapat mengampu banyak mata kuliah.
PROGRAM_STUDI — MAHASISWA1 : N
MAHASISWA — KRS1 : N
MATA_KULIAH — KRS1 : N
DOSEN — MATA_KULIAH1 : N
