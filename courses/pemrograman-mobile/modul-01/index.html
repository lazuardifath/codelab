D. Instalasi Tools

Ikuti langkah berikut secara berurutan. Jangan melompat ke Flutter sebelum Git terpasang.

1. Git

  1. Buka git-scm.com/download/win dan unduh installer 64-bit.
  2. Jalankan installer. Pilih opsi default di setiap langkah — tidak perlu mengubah apapun.
  3. Buka terminal baru (Command Prompt atau PowerShell) dan verifikasi:
git --version

Jika muncul versi seperti git version 2.x.x, Git sudah terpasang dengan benar.

2. Flutter SDK

  1. Buka docs.flutter.dev dan unduh Flutter SDK versi stable terbaru.
  2. Ekstrak ke C:\flutter. Hindari folder yang mengandung spasi seperti C:\Program Files.
  3. Tambahkan C:\flutter\bin ke PATH sistem:
    • Tekan Win + R, ketik sysdm.cpl, tekan Enter.
    • Buka tab Advanced → klik Environment Variables.
    • Pada bagian System Variables, pilih baris Path → klik Edit → klik New.
    • Ketik C:\flutter\bin → OK di semua jendela yang terbuka.
  4. Tutup semua terminal yang sedang buka, lalu buka terminal baru dan verifikasi:
flutter --version

3. Visual Studio Code

  1. Unduh dari code.visualstudio.com dan instal dengan opsi default.
  2. Buka VS Code → panel Extensions dengan Ctrl+Shift+X.
  3. Cari dan instal ekstensi bernama Flutter. Ekstensi Dart akan ikut terpasang otomatis.

Setelah ekstensi terpasang, VS Code dapat menjalankan aplikasi Flutter, memberikan autocomplete Dart, mendeteksi error sebelum kode dikompilasi, dan menampilkan widget documentation saat hover.

4. Android Studio dan emulator

  1. Unduh dari developer.android.com/studio dan instal dengan opsi default.
  2. Buka Android Studio → SDK Manager → pastikan Android SDK dan Android SDK Command-line Tools tercentang → Apply.
  3. Buka Device Manager → Create Virtual Device → pilih Pixel 6 → pilih system image API 34 → Finish.
  4. Klik tombol Play pada virtual device yang baru dibuat untuk menjalankan emulator.

Menggunakan perangkat fisik (opsional): aktifkan Developer Options di pengaturan Android (biasanya dengan mengetuk Build Number tujuh kali), nyalakan USB Debugging, hubungkan kabel data ke komputer, lalu izinkan debugging saat dialog muncul di layar perangkat.

E. Dart Dasar

Semua kode Flutter ditulis dalam Dart. Kuasai bagian ini sebelum membaca kode Flutter karena sintaks ini akan muncul berulang kali tanpa penjelasan ulang di modul berikutnya. Gunakan DartPad untuk mencoba semua contoh tanpa perlu Flutter terpasang.

var, final, dan const

void main() {
  var nama = 'Budi';         // tipe disimpulkan otomatis sebagai String
  nama = 'Siti';              // boleh diubah

  final nim = '2024001';      // diinisialisasi sekali, tidak bisa diubah lagi
  // nim = '2024002';         // error: nilai final tidak dapat diubah

  const appName = 'UNIMUGO'; // tetap sejak kompilasi, paling efisien untuk nilai konstan
  print('$appName - $nim - $nama');
}

Gunakan const untuk nilai yang benar-benar tetap dan diketahui saat kompilasi. Gunakan final untuk nilai yang ditetapkan satu kali saat runtime. Gunakan var hanya jika nilainya memang perlu berubah.

Tipe data dan null safety

void main() {
  String judul = 'Workshop Flutter';
  int semester = 4;
  double ipk = 3.75;
  bool aktif = true;

  // Tanda ? berarti variabel boleh bernilai null
  String? email;            // belum diisi, nilainya null
  print(email);             // null

  email = 'budi@unimugo.ac.id';
  print(email);             // budi@unimugo.ac.id

  // Operator ?? : gunakan nilai kanan jika nilai kiri null
  String tampilEmail = email ?? 'Email belum diisi';
  print(tampilEmail);

  // String interpolation: $variabel atau ${ekspresi}
  print('$judul - Semester $semester - IPK: $ipk');
  print('Status: ${aktif ? "Aktif" : "Tidak aktif"}');
}

Null safety mencegah error umum: mengakses nilai yang belum diinisialisasi. Dart mengharuskan kode secara eksplisit menyatakan apakah sebuah variabel bisa bernilai null atau tidak, sehingga banyak bug dapat ditangkap sebelum aplikasi dijalankan.

Fungsi dan named parameter

// Fungsi biasa dengan tipe eksplisit
int tambah(int a, int b) {
  return a + b;
}

// Arrow function untuk fungsi satu ekspresi
String sapa(String nama) => 'Halo, $nama!';

// Named parameters: ditulis dalam {} dan dipanggil dengan nama
// required = wajib diisi, tanpa default value
// Tanpa required = opsional, harus ada default value
void cetakAgenda({
  required String judul,
  String lokasi = 'Kampus UNIMUGO',
}) {
  print('$judul · $lokasi');
}

void main() {
  print(tambah(3, 4));                    // 7
  print(sapa('Budi'));                    // Halo, Budi!

  cetakAgenda(judul: 'Workshop Git');
  cetakAgenda(judul: 'Seminar AI', lokasi: 'Auditorium');
}

Named parameter banyak digunakan di Flutter — hampir setiap widget menggunakan pola ini. Memahaminya sekarang akan membuat kode Flutter jauh lebih mudah dibaca.

Class dan constructor

class Mahasiswa {
  final String nama;
  final String nim;
  final int semester;

  // const constructor: objek dapat dibuat saat kompilasi
  const Mahasiswa({
    required this.nama,
    required this.nim,
    required this.semester,
  });

  // Getter: properti yang dihitung dari properti lain
  String get info => '$nama ($nim) · Semester $semester';

  // Method dengan return type bool
  bool get masihAktif => semester <= 8;
}

void main() {
  const mhs = Mahasiswa(
    nama: 'Budi Santoso',
    nim: '2024001',
    semester: 4,
  );

  print(mhs.info);        // Budi Santoso (2024001) · Semester 4
  print(mhs.masihAktif);  // true
}

Pola class dengan const constructor dan named parameter adalah pola standar Flutter. Setiap widget Flutter pada dasarnya adalah class seperti ini yang mewarisi StatelessWidget atau StatefulWidget.

F. Konsep Flutter

StatelessWidget dan StatefulWidget

Semua elemen antarmuka Flutter adalah widget. Ada dua jenis utama:

JenisKapan digunakanContoh penggunaan
StatelessWidget Tampilan ditentukan sepenuhnya oleh data dari parent, tidak perlu berubah setelah dibuat Label teks, kartu statis, ikon, header
StatefulWidget Ada data internal yang dapat berubah akibat interaksi pengguna atau pembaruan data Tombol toggle, counter, form, animasi 
// StatelessWidget: tidak ada state internal yang berubah
class LabelNama extends StatelessWidget {
  final String nama;
  const LabelNama({super.key, required this.nama});

  @override
  Widget build(BuildContext context) {
    return Text(nama, style: const TextStyle(fontWeight: FontWeight.bold));
  }
}

// StatefulWidget: ada nilai yang bisa berubah (nilai counter)
class Penghitung extends StatefulWidget {
  const Penghitung({super.key});

  @override
  State<Penghitung> createState() => _PenghitungState();
}

class _PenghitungState extends State<Penghitung> {
  int nilai = 0; // state: nilai ini bisa berubah

  @override
  Widget build(BuildContext context) {
    return Column(
      children: [
        Text('Nilai: $nilai'),
        ElevatedButton(
          // setState() memberi tahu Flutter untuk membangun ulang widget ini
          onPressed: () => setState(() => nilai++),
          child: const Text('Tambah'),
        ),
      ],
    );
  }
}

Jangan pernah mengubah variabel state tanpa membungkusnya dalam setState(). Tanpa setState(), nilai berubah di memori tetapi tampilan tidak diperbarui.

Widget tree dan pendekatan deklaratif

Flutter menyusun antarmuka sebagai hierarki widget. Kode mendeskripsikan tampilan berdasarkan state saat ini. Ketika state berubah, Flutter membangun ulang bagian widget yang terdampak — bukan seluruh halaman. 

MaterialApp              <-- konfigurasi aplikasi (tema, rute)
 ⌊— Scaffold             <-- struktur halaman (appBar, body)
     ├— AppBar
     │    ⌊— Text          <-- judul halaman
     ⌊— Padding
          ⌊— Column       <-- susun widget secara vertikal
               ├— Text     <-- baris pertama
               ⌊— Button  <-- tombol aksi

Arti const pada widget

// Tanpa const: Flutter membuat objek widget baru setiap kali rebuild
Text('Judul Tetap')

// Dengan const: Flutter menggunakan instance yang sama, lebih efisien
const Text('Judul Tetap')

Gunakan const pada widget yang konfigurasinya tidak berubah. VS Code akan menampilkan hint jika const bisa ditambahkan tapi belum ada. Mengikuti saran ini adalah kebiasaan baik sejak awal.

G. Ekosistem Mobile

Memahami lanskap pengembangan mobile membantu menentukan teknologi yang tepat untuk proyek tertentu.

Pendekatan Cara kerja Kelebihan Pertimbangan Contoh teknologi
Native Kode dan UI khusus tiap platform Performa optimal, akses API perangkat paling lengkap Perlu tim atau kode terpisah per platform Kotlin/Java (Android), Swift (iOS)
Hybrid Aplikasi web berjalan dalam pembungkus native Memanfaatkan keterampilan web yang sudah ada Performa dan akses API perangkat terbatas Ionic, Cordova
Cross-platform Satu basis kode dikompilasi ke tiap platform Efisiensi pengembangan, UI konsisten Perlu memahami karakter tiap platform Flutter, React Native, KMP

Flutter menggunakan engine rendering sendiri (Impeller/Skia) sehingga UI tampak konsisten di semua platform tanpa bergantung pada komponen native. Dart dikompilasi ke kode mesin (AOT) untuk build rilis, dan dijalankan dengan JIT saat pengembangan untuk mendukung hot reload.

3. Fungsi validasi

Buat file baru: lib/utils/validasi.dart

// Mengembalikan null jika valid, atau String pesan error jika tidak valid.
// Pola String? ini adalah standar validator yang digunakan TextFormField di Flutter.
String? validasiJudul(String judul) {
  if (judul.trim().isEmpty) {
    return 'Judul agenda tidak boleh kosong';
  }
  if (judul.trim().length < 5) {
    return 'Judul terlalu pendek, minimal 5 karakter';
  }
  return null; // null berarti valid
}

String? validasiTanggal(String tanggal) {
  if (tanggal.trim().isEmpty) {
    return 'Tanggal tidak boleh kosong';
  }
  return null;
}

trim() menghapus spasi di awal dan akhir string, sehingga input yang hanya berisi spasi tetap dianggap kosong. Pola ini konsisten dengan cara Flutter menangani validasi form di modul berikutnya.

5. Uji validasi

Tambahkan sementara di awal main() untuk memverifikasi fungsi bekerja:

void main() {
  // Pengujian validasi — hapus setelah selesai
  assert(validasiJudul('') == 'Judul agenda tidak boleh kosong');
  assert(validasiJudul('   ') == 'Judul agenda tidak boleh kosong');
  assert(validasiJudul('Git') == 'Judul terlalu pendek, minimal 5 karakter');
  assert(validasiJudul('Workshop Flutter') == null);
  print('Semua validasi lolos');

  runApp(const UnimugoEventApp());
}

assert() akan melempar error jika kondisinya salah — berguna untuk memverifikasi logika selama pengembangan tanpa framework testing penuh. Hapus baris assert setelah yakin fungsi bekerja benar.

L. Eksperimen

  1. StatefulWidget: ubah AgendaTile menjadi StatefulWidget. Tambahkan variabel bool disukai = false dan IconButton yang mengubahnya antara ikon hati kosong dan hati penuh. Amati peran setState().
  2. Null safety: tampilkan agenda.deskripsi pada tile. Gunakan operator ?? agar agenda tanpa deskripsi menampilkan teks 'Tidak ada deskripsi'. Bandingkan hasilnya antara agenda yang punya deskripsi dan yang tidak.
  3. const vs var: ubah const agendaDummy menjadi var agendaDummy. Tambahkan satu agenda baru menggunakan method add() di dalam main() sebelum runApp(). Amati apakah daftar bertambah dan mengapa const tidak mengizinkan ini.

M. Tugas Praktikum

Kembangkan project unimugo_event dengan ketentuan berikut:

  1. Tambahkan minimal tiga agenda baru ke agendaDummy dengan kategori yang berbeda-beda.
  2. Buat widget KategoriBadge yang menerima parameter String kategori dan menampilkannya sebagai chip kecil berwarna. Warna chip dapat berbeda berdasarkan nilai kategori (gunakan switch atau Map).
  3. Tampilkan KategoriBadge di dalam AgendaTile menggantikan atau melengkapi CircleAvatar.
  4. Tambahkan fungsi List<Agenda> filterByKategori(String kategori) di file agenda_data.dart yang mengembalikan hanya agenda dengan kategori tertentu. Uji fungsi ini dengan assert di main().
  5. Commit setiap perubahan yang bermakna dengan pesan commit yang jelas dan menggunakan awalan feat:, fix:, atau refactor:.
Sertakan screenshot aplikasi berjalan dan output flutter doctor pada folder docs/screenshots/ di repository.
