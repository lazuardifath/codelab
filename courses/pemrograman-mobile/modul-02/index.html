B. Tujuan Pembelajaran

Mahasiswa tidak sekadar mengikuti kode, tetapi memahami alasan di balik setiap keputusan UI. Setelah praktikum, mahasiswa mampu:

  • menjelaskan widget, widget tree, configuration, state, UI, dan declarative UI;
  • membedakan StatelessWidget dan StatefulWidget serta memakai setState();
  • memahami build(), BuildContext, dan lifecycle state;
  • menggunakan Text, Icon, Container, Padding, Card, SizedBox, Row, Column, Expanded, Flexible, ListView, dan GridView;
  • menjelaskan constraint dan memperbaiki overflow;
  • membuat responsive UI dengan LayoutBuilder dan membedakannya dari MediaQuery;
  • menerapkan ThemeData, ColorScheme, light mode, dark mode, dan accessibility dasar;
  • membaca widget tree, melakukan debugging layout, serta membangun halaman secara mandiri.

D. Konsep Dasar: Bagaimana Flutter Menggambar UI?

D.1 Apa itu UI?

UI adalah bagian aplikasi yang berinteraksi dengan pengguna: teks, tombol, gambar, kartu, form, navigasi, daftar, dan dialog. Dalam Flutter, hampir seluruh bagian UI direpresentasikan sebagai widget.

D.2 Widget dan widget tree

Widget adalah konfigurasi immutable untuk menjelaskan tampilan. Widget disusun di dalam widget lain sehingga membentuk tree.

MaterialApp └── Scaffold ├── AppBar └── Body └── Column ├── Text ├── SizedBox └── ElevatedButton

E. Memahami Widget

Widget Flutter pada bagian ini dibagi menjadi tiga kelompok berdasarkan tanggung jawabnya. Pembagian ini membantu mahasiswa membaca kode dan memilih widget yang tepat.

E.1 Widget tampilan

Widget tampilan menampilkan informasi kepada pengguna. Widget ini biasanya tidak menerima input langsung.

widget_tampilan.dart
Text('Halo Flutter')
Icon(Icons.home)

Text menampilkan tulisan, sedangkan Icon menampilkan simbol dari icon set Flutter. Keduanya dapat menjadi child dari widget lain.

E.2 Widget interaksi

Widget interaksi menerima tindakan pengguna seperti tap. Callback onPressed dijalankan ketika tombol ditekan.

widget_interaksi.dart
ElevatedButton(
  onPressed: () {
    // aksi dijalankan setelah tombol ditekan
  },
  child: const Text('Simpan'),
)

Tombol belum otomatis mengubah UI. Jika aksi harus mengubah data atau tampilan, simpan perubahan melalui state, misalnya setState() pada StatefulWidget.

E.3 Widget layout dan wadah

Widget layout mengatur ukuran, jarak, posisi, atau hubungan antar-widget. Widget ini membungkus widget lain melalui properti child atau children.

widget_layout.dart
Container(
  padding: const EdgeInsets.all(16),
  child: Card(
    child: Padding(
      padding: const EdgeInsets.all(12),
      child: const Text('Hello'),
    ),
  ),
)

const SizedBox(height: 16)
  • Container menyediakan wadah untuk dekorasi, padding, margin, atau ukuran.
  • Padding memberi ruang di dalam batas child.
  • Card memberi wadah visual dengan bentuk dan elevation.
  • SizedBox memberi jarak atau ukuran yang terkontrol.

E.4 Contoh widget tree

Scaffold └── Body └── Padding └── Card └── Column ├── Icon ├── Text └── ElevatedButton

Kesimpulannya: tampilan menyampaikan informasi, interaksi menerima aksi pengguna, dan layout/wadah mengatur bagaimana semuanya ditempatkan. Widget yang lebih besar dibangun dengan menggabungkan ketiga kelompok tersebut.

F. Praktik 1 - Membuat UI Paling Sederhana

Buka lib/main.dart. Gunakan kode lengkap berikut:

lib/main.dart
import 'package:flutter/material.dart';

void main() {
  runApp(const MyApp());
}

class MyApp extends StatelessWidget {
  const MyApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      home: Scaffold(
        appBar: AppBar(title: const Text('UNIMUGO Event')),
        body: const Center(child: Text('Selamat Datang')),
      ),
    );
  }
}

Amati urutan MaterialApp → Scaffold → AppBar dan Body → Center → Text.

G. Memahami build() dan BuildContext

build() tidak berarti menggambar layar sekali. Artinya: deskripsikan UI berdasarkan configuration dan state saat ini. Flutter dapat memanggilnya kembali ketika input berubah.

State / Configuration
build(context)
Widget tree / UI

BuildContext adalah referensi posisi widget di dalam tree. Context dipakai untuk mengakses theme, ukuran lokal, Navigator, dan ancestor lain. Jangan menyimpan context sembarangan atau memakainya setelah widget tidak lagi aktif.

H. Memahami Declarative UI

Imperatif berarti memberi perintah langkah demi langkah. Declarative berarti mendeskripsikan tampilan yang diinginkan untuk kondisi saat ini.

login_label.dart
Text(
  isLogin ? 'Selamat Datang' : 'Silakan Login',
)

Jika isLogin berubah, kita memperbarui state lalu mendeskripsikan UI baru. Kita tidak perlu mencari widget lama dan mengganti teksnya secara manual.

I. StatelessWidget vs StatefulWidget

Perbedaan utama bukan ada atau tidaknya tombol. Pertanyaannya: apakah widget perlu menyimpan state lokal yang berubah selama widget hidup?

I.1 StatelessWidget

Gunakan ketika UI bergantung pada constructor parameter atau data dari parent. Konfigurasinya immutable.

lib/widgets/judul_halaman.dart
class JudulHalaman extends StatelessWidget {
  const JudulHalaman({super.key, required this.title});
  final String title;

  @override
  Widget build(BuildContext context) => Text(
    title,
    style: Theme.of(context).textTheme.titleLarge,
  );
}

I.2 StatefulWidget

Gunakan ketika data lokal berubah karena tap, input, timer, animasi, atau proses sementara. Configuration tetap immutable; data berubah disimpan dalam objek State.

lib/pages/counter_page.dart
class CounterPage extends StatefulWidget {
  const CounterPage({super.key});
  @override
  State<CounterPage> createState() => _CounterPageState();
}

class _CounterPageState extends State<CounterPage> {
  int counter = 0;

  void tambah() {
    setState(() {
      counter++;
    });
  }

  @override
  Widget build(BuildContext context) => Column(
    mainAxisAlignment: MainAxisAlignment.center,
    children: [
      Text('$counter', style: const TextStyle(fontSize: 40)),
      ElevatedButton(onPressed: tambah, child: const Text('Tambah')),
    ],
  );
}

Catatan: counter++ mengubah variabel Dart, tetapi setState() memberi tahu Flutter bahwa UI perlu dibangun ulang.

AspekStatelessWidgetStatefulWidget
State lokal berubah?TidakYa, pada objek State
ContohAgendaCard, judul, iconCounter, filter, form lokal
setState()TidakYa untuk state lokal
RebuildSaat parent memberi konfigurasi baruSaat parent rebuild atau setState dipanggil

I.3 Lifecycle StatefulWidget

  1. createState() membuat object State.
  2. initState() dipanggil sekali untuk controller atau listener.
  3. build() membaca state dan menghasilkan UI.
  4. setState() menandai perubahan state lokal.
  5. dispose() membersihkan controller, listener, dan resource.
State milik siapa? Letakkan state sedekat mungkin dengan widget yang menggunakannya. Jika beberapa sibling membutuhkannya, naikkan ke parent terdekat. Data lintas halaman lebih tepat dikelola dengan state management.

J. Praktik 2 - Counter Jumlah Event

Ubah counter menjadi jumlah peserta event. Buat tombol [-] dan [+]. Nilai tidak boleh kurang dari nol.

logika_counter.dart
void kurang() {
  if (counter > 0) {
    setState(() {
      counter--;
    });
  }
}

Urutan: user action → method → state berubah → setState() → build() → UI baru.

K. Memahami Layout Flutter

Column menyusun child vertikal dan Row menyusun child horizontal.

layout.dart
Column(
  children: [
    const Text('Judul Event'),
    const Text('12 Oktober 2026'),
    ElevatedButton(onPressed: () {}, child: const Text('Detail')),
  ],
)

Row(
  children: [
    const Icon(Icons.event),
    const SizedBox(width: 8),
    const Text('Workshop Flutter'),
  ],
)

Pada Row, main axis horizontal. Pada Column, main axis vertikal. Coba mainAxisAlignment.center dan crossAxisAlignment.start, center, serta end.

K.1 Expanded dan Flexible

Text panjang dalam Row dapat menyebabkan RIGHT OVERFLOWED BY XX PIXELS. Gunakan ruang fleksibel.

row_aman.dart
Row(
  children: [
    const Icon(Icons.event),
    const SizedBox(width: 8),
    Expanded(child: Text(longTitle)),
    const Icon(Icons.arrow_forward),
  ],
)

K.2 Constraint

Parent memberi batas, child memilih ukuran dalam batas tersebut, lalu parent menentukan posisi. Hindari terlalu banyak ukuran tetap seperti width: 500 jika UI berjalan pada banyak layar.

L. Praktik 3 - Membuat AgendaCard

Mulai gunakan studi kasus UNIMUGO Event dengan data dummy lokal.

lib/models/agenda.dart
class Agenda {
  final String judul;
  final String kategori;
  final String tanggal;

  const Agenda({
    required this.judul,
    required this.kategori,
    required this.tanggal,
  });
}

const agenda = [
  Agenda(judul: 'Workshop Git untuk Proyek TI', kategori: 'Laboratorium', tanggal: '12 Okt 2026'),
  Agenda(judul: 'Seminar Karier Teknologi', kategori: 'Program Studi', tanggal: '19 Okt 2026'),
  Agenda(judul: 'Pelatihan UI/UX', kategori: 'Himpunan Mahasiswa', tanggal: '25 Okt 2026'),
];
lib/widgets/agenda_card.dart
class AgendaCard extends StatelessWidget {
  const AgendaCard({super.key, required this.agenda});
  final Agenda agenda;

  @override
  Widget build(BuildContext context) => Semantics(
    label: '${agenda.judul}, ${agenda.kategori}, ${agenda.tanggal}',
    child: Card(
      child: Padding(
        padding: const EdgeInsets.all(16),
        child: Column(
          crossAxisAlignment: CrossAxisAlignment.start,
          children: [
            Text(agenda.kategori, style: Theme.of(context).textTheme.labelMedium),
            const SizedBox(height: 8),
            Text(agenda.judul, style: Theme.of(context).textTheme.titleMedium),
            const SizedBox(height: 12),
            Row(children: [const Icon(Icons.calendar_today, size: 16), const SizedBox(width: 8), Text(agenda.tanggal)]),
          ],
        ),
      ),
    ),
  );
}

AgendaCard sengaja menjadi StatelessWidget: ia hanya menerima data dan merendernya. State filter atau pilihan kategori berada di parent.

M. Menampilkan Banyak Data: List dan Grid

list_builder.dart
ListView.builder(
  itemCount: agenda.length,
  itemBuilder: (context, index) => AgendaCard(agenda: agenda[index]),
)

Hubungannya adalah list data → itemCount → index → agenda[index] → AgendaCard. Grid dipakai saat ruang horizontal cukup untuk beberapa kolom.

N. Responsive UI

Jangan berpikir Android memiliki ukuran tertentu dan tablet memiliki ukuran tertentu. Tanyakan berapa ruang yang tersedia untuk UI. Gunakan LayoutBuilder.

responsive_grid.dart
LayoutBuilder(
  builder: (context, constraints) {
    final width = constraints.maxWidth;
    final columns = width >= 720 ? 3 : width >= 600 ? 2 : 1;

    return GridView.builder(
      gridDelegate: SliverGridDelegateWithFixedCrossAxisCount(
        crossAxisCount: columns,
        crossAxisSpacing: 16,
        mainAxisSpacing: 16,
        childAspectRatio: 1.5,
      ),
      itemCount: agenda.length,
      itemBuilder: (context, index) => AgendaCard(agenda: agenda[index]),
    );
  },
)
< 600 px → 1 kolom 600-719 px → 2 kolom ≥ 720 px → 3 kolom

N.1 LayoutBuilder vs MediaQuery

APIInformasiPenggunaan
MediaQueryUkuran window/screen secara umumOrientasi, safe area, preferensi sistem
LayoutBuilderConstraint yang diberikan parentResponsive component berdasarkan ruang aktual

Untuk komponen yang berada di panel sempit, LayoutBuilder sering lebih tepat daripada lebar layar global.

O. Theme dan Dark Mode

Gunakan satu sumber warna dan typography agar UI konsisten. Jangan hardcode warna yang sebenarnya bagian dari theme.

lib/theme/app_theme.dart
final lightTheme = ThemeData(
  colorScheme: ColorScheme.fromSeed(seedColor: Colors.green),
  useMaterial3: true,
);

final darkTheme = ThemeData(
  colorScheme: ColorScheme.fromSeed(
    seedColor: Colors.green,
    brightness: Brightness.dark,
  ),
  useMaterial3: true,
);

MaterialApp(
  theme: lightTheme,
  darkTheme: darkTheme,
  themeMode: ThemeMode.system,
  home: const EventPage(),
)

Di dalam widget gunakan Theme.of(context).colorScheme.primary atau style dari textTheme. Uji light dan dark mode: teks, background, icon, card, dan tombol harus tetap terbaca.

P. Accessibility Dasar

Accessibility membuat UI dapat digunakan lebih banyak pengguna. Jangan menyampaikan informasi hanya melalui warna.

  • Gunakan teks status, bukan hanya hijau/merah.
  • Gunakan label bermakna pada tombol dan elemen interaktif.
  • Gunakan ukuran teks yang nyaman; jangan mengecilkan font hanya agar semua muat.
  • Gunakan Semantics untuk informasi yang perlu dibaca screen reader.
accessible_card.dart
Semantics(
  label: 'Workshop Git untuk Proyek Teknologi Informasi',
  child: AgendaCard(agenda: agenda.first),
)

Q. Praktik 4 - Filter Kategori dan Empty State

Filter adalah state yang relevan dengan aplikasi. State pilihan kategori menyebabkan data difilter dan UI dibangun ulang.

filter_logic.dart
String? selectedCategory;

final filteredAgenda = selectedCategory == null
    ? agenda
    : agenda.where((item) => item.kategori == selectedCategory).toList();

if (filteredAgenda.isEmpty) {
  return const Center(child: Text('Belum ada agenda yang sesuai.'));
}

Minimal UI perlu memikirkan loading, success, empty, dan error meskipun data sekarang masih dummy. Jangan biarkan layar kosong tanpa penjelasan.

T. Debugging Challenge

  1. Overflow: gunakan Row dengan icon, Text(longTitle), dan icon panah. Jelaskan mengapa overflow terjadi lalu perbaiki menggunakan Expanded.
  2. State tidak berubah: ubah counter++ tanpa setState(). Temukan mengapa UI tidak berubah.
  3. Responsive: ubah GridView dengan crossAxisCount: 2 tetap menjadi LayoutBuilder dengan breakpoint.

U. Eksperimen

  1. Ubah breakpoint 600 menjadi 720 dan amati.
  2. Tambahkan tiga kolom pada layar lebih lebar.
  3. Ubah childAspectRatio menjadi 1.0, 1.5, dan 2.0.
  4. Aktifkan dark mode dan temukan tiga masalah readability.
  5. Hilangkan Expanded dari Row dan jelaskan penyebab overflow.
