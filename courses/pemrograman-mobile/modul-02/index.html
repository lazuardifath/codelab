UI Deklaratif dan Desain Responsif

Menyusun dashboard kegiatan mahasiswa dengan widget Flutter yang dapat beradaptasi pada ukuran layar berbeda.

A. Identitas Praktikum

Pertemuan: 2 · Prasyarat: Modul 01, Dart dasar.

B. Capaian Pembelajaran

  • Mahasiswa mampu menjelaskan hubungan widget, konfigurasi, dan state dalam UI deklaratif.
  • Mahasiswa mampu menggunakan StatelessWidget, StatefulWidget, Row, Column, dan Expanded.
  • Mahasiswa mampu merancang layout yang nyaman pada layar ponsel dan tablet.
  • Mahasiswa mampu menerapkan theme, dark mode, dan aksesibilitas dasar.

C. Konsep Ringkas

Pada UI deklaratif, kode menggambarkan tampilan berdasarkan data atau state saat ini. Perubahan state memicu pembangunan ulang bagian tampilan yang relevan. Gunakan LayoutBuilder untuk merespons ruang yang tersedia, bukan mengandalkan ukuran piksel tetap.

Widget build(BuildContext context) {
  return LayoutBuilder(
    builder: (context, constraints) {
      final kolom = constraints.maxWidth > 600 ? 2 : 1;
      return GridView.count(crossAxisCount: kolom);
    },
  );
}

D. Studi Kasus

Kembangkan dashboard UNIMUGO Event yang menampilkan kartu agenda. Pada layar sempit gunakan satu kolom; pada layar lebar gunakan dua kolom. Informasi tetap dapat dibaca ketika tema gelap diaktifkan.

E. Langkah Praktikum

Langkah 1 — Buat model data dummy

class Agenda {
  final String judul;
  final String kategori;
  final String tanggal;

  const Agenda(this.judul, this.kategori, this.tanggal);
}

const agenda = [
  Agenda('Workshop Git untuk Proyek TI', 'Laboratorium', '12 Okt 2026'),
  Agenda('Seminar Karier Teknologi', 'Program Studi', '19 Okt 2026'),
];

Langkah 2 — Bangun kartu agenda

Buat widget AgendaCard yang menerima objek Agenda dari parent. Gunakan Card, Padding, dan Semantics agar informasi memiliki label yang jelas.

Langkah 3 — Atur layout responsif

Gunakan LayoutBuilder untuk memilih jumlah kolom. Uji pada emulator ponsel dan ukuran tablet. Pastikan tidak ada overflow horizontal.

Langkah 4 — Terapkan tema

Definisikan ColorScheme.fromSeed, theme, dan darkTheme pada MaterialApp. Gunakan kontras yang memadai dan jangan menyampaikan status hanya melalui warna.

F. Validasi Output

  • Tampilan satu kolom pada lebar layar ponsel.
  • Tampilan dua kolom pada layar tablet/desktop.
  • Teks kartu tidak terpotong dan tidak overflow.
  • Mode terang dan gelap tetap terbaca.

G. Eksperimen

Ubah batas lebar dari 600 menjadi 720 dan tambahkan breakpoint tiga kolom. Bandingkan pengalaman membaca pada emulator yang berbeda. Tambahkan filter kategori tanpa mengubah data sumber.

H. Tugas Praktikum

Rancang halaman daftar kegiatan mahasiswa dengan minimal enam data dummy. Sertakan keadaan kosong ketika filter tidak menemukan agenda dan berikan label aksesibel pada tombol filter.

I. Refleksi

  1. Bagian mana yang termasuk konfigurasi dan mana yang termasuk state?
  2. Mengapa ukuran tetap berisiko menyebabkan overflow?
  3. Bagaimana Anda memeriksa aksesibilitas selain melihat warna?
