A. Gambaran Umum

Pada Modul 02 mahasiswa belajar widget, layout, state lokal, responsive layout, theme, dan accessibility. Modul ini menjawab: bagaimana aplikasi berpindah halaman, membawa data antarhalaman, mengelola state, dan menampilkan kondisi aplikasi secara benar?

Agenda List │ klik event ↓ Detail Event │ klik Daftar ↓ Form Registrasi │ berhasil ↓ Konfirmasi

Urutan konsep: Navigation → Routing → Passing Parameters → State → Async State → Loading/Error/Empty/Success → State Management.

Catatan scope: modul ini memakai data lokal/dummy terlebih dahulu. PokeAPI tidak digunakan di sini dan akan menjadi konteks API pada pertemuan 9.

Fundamental

D. Bagian 1 - Memahami Navigation

D.1 Apa itu Navigation?

Navigation adalah mekanisme berpindah dari satu screen/page ke screen/page lain. Contoh: Home → Detail → Checkout. Flutter menyediakan Navigator sebagai mekanisme dasar.

D.2 Navigation Stack

Bayangkan stack seperti tumpukan buku.

Awal: [Page 1] push: [Page 1] [Page 2] push lagi: [Page 1] [Page 2] [Page 3] pop: [Page 1] [Page 2]

push menambahkan halaman. pop menghapus halaman paling atas, sehingga back tidak kembali ke halaman kosong.

E. Praktik 1 - Navigation Paling Sederhana

Buat project Flutter atau gunakan project dari modul sebelumnya. Struktur mini-lab:

lib/ ├── main.dart └── features/lab/ ├── page_one.dart ├── page_two.dart └── page_three.dart

F. Eksperimen Stack dan Lab Try and Error

Mahasiswa wajib menggambar stack pada setiap kondisi:

  1. Aplikasi dibuka: [Page 1].
  2. Klik Page 2: [Page 1, Page 2].
  3. Klik Page 3: [Page 1, Page 2, Page 3].
  4. Tekan back: [Page 1, Page 2].

Kesalahan yang disengaja

Ganti Navigator.pop(context) menjadi:

bug_push.dart
Navigator.push(
  context,
  MaterialPageRoute(builder: (_) => const PageThree()),
);

Klik tombol lima kali. Stack menjadi Page 1 → Page 2 → Page 3 → Page 3 → Page 3 → Page 3 → Page 3. Page 3 tidak menggantikan Page 3 sebelumnya; setiap push() membuat route baru dan stack terus bertambah.

Pertanyaan debugging: apa dampaknya terhadap memory dan tombol back? Mengapa aplikasi nyata tidak boleh sembarangan melakukan push?

G.1 Dari Constructor ke Route Parameter

Constructor cocok untuk alur kecil. Aplikasi yang memerlukan deep link, browser URL, route guard, dan nested route membutuhkan routing yang terstruktur.

H. Declarative Routing dengan GoRouter

Routing deklaratif mendefinisikan hubungan URL → Route → Page.

terminal
flutter pub add go_router
lib/app.dart
final router = GoRouter(
  initialLocation: '/',
  routes: [
    GoRoute(path: '/', builder: (_, __) => const AgendaListPage()),
    GoRoute(
      path: '/agenda/:id',
      builder: (context, state) => AgendaDetailPage(
        id: state.pathParameters['id']!,
      ),
    ),
  ],
);

MaterialApp.router(routerConfig: router)

:id adalah parameter dinamis. URL valid: /agenda/a1, /agenda/a2, dan /agenda/a3.

nested_route.dart
GoRoute(
  path: '/agenda/:id',
  routes: [
    GoRoute(
      path: 'registrasi',
      builder: (context, state) => RegistrationPage(
        id: state.pathParameters['id']!,
      ),
    ),
  ],
)

Nested route tersebut menghasilkan URL /agenda/a2/registrasi. Route anak melanjutkan parameter id dari route induk.

navigation_with_router.dart
context.go('/agenda/${agenda.id}'); // lokasi
context.push('/agenda/${agenda.id}'); // stack

go() berpindah ke lokasi, sedangkan push() menambahkan route ke stack. Buka langsung /agenda/a2 untuk menguji deep link.

I. Bagian 2 - Memahami State

State adalah data atau kondisi yang dapat berubah dan memengaruhi UI. Contoh: selectedCategory, isLoading, counter, agendaList, dan isLoggedIn.

I.1 Local State

local_state.dart
bool isFavorite = false;

setState(() {
  isFavorite = !isFavorite;
});

Gunakan setState() jika state sederhana, lokal, hanya dipakai satu screen/widget, dan tidak dibagikan.

I.2 Shared State

Agenda Repository ↓ Agenda State ┌──┴──┐ ↓ ↓ List Detail

Jika list dan detail memakai data favorite yang sama, state yang tersebar menjadi sulit dirawat. Di sinilah state management dibutuhkan.

J. Riverpod dan ProviderScope

Riverpod digunakan ketika dependency, lifecycle, dan shared state perlu dikelola lebih terstruktur.

terminal
flutter pub add flutter_riverpod
lib/main.dart
void main() {
  runApp(const ProviderScope(child: App()));
}

ProviderScope menyediakan container Riverpod bagi widget turunannya. Tanpa wrapper ini, provider tidak memiliki scope untuk dibaca.

K. Repository dan Dummy Data

Repository memisahkan UI dari detail sumber data.

UI → State → Repository → Data Source
lib/data/agenda_repository.dart
class AgendaRepository {
  Future<List<Agenda>> findAll() async {
    await Future.delayed(const Duration(seconds: 1));
    return localAgendas;
  }

  Future<Agenda> findById(String id) async {
    await Future.delayed(const Duration(seconds: 1));
    return localAgendas.firstWhere((item) => item.id == id);
  }
}

Kita belum memakai HTTP agar mahasiswa memahami abstraksi lebih dahulu. Pada pertemuan API, data source dapat diganti menjadi REST API tanpa mengubah seluruh UI.

L. Async UI dan Empat Kondisi

Future merepresentasikan pekerjaan yang selesai kemudian. Gunakan delay untuk mensimulasikan request jaringan, bukan untuk membuat aplikasi lambat.

REQUEST ↓ LOADING ↓ selesai SUCCESS / EMPTY / ERROR Loading: Memuat agenda... Success: 6 agenda ditemukan Empty: Belum ada agenda Error: Gagal memuat agenda - [Coba Lagi]

Aplikasi nyata dapat menghadapi server lambat, internet mati, database kosong, atau request gagal. UI harus merepresentasikan kondisi tersebut.

M. Model State dan State Machine

State eksplisit lebih jelas daripada banyak boolean yang saling bertentangan.

lib/state/agenda_list_state.dart
sealed class AgendaListState {}
class AgendaLoading extends AgendaListState {}
class AgendaEmpty extends AgendaListState {}
class AgendaSuccess extends AgendaListState {
  AgendaSuccess(this.items);
  final List<Agenda> items;
}
class AgendaFailure extends AgendaListState {
  AgendaFailure(this.message);
  final String message;
}
LOADING ↓ request selesai SUCCESS / EMPTY / ERROR ↓ retry LOADING

UI membaca state lalu menerjemahkannya menjadi progress indicator, daftar, pesan empty, atau error dengan retry.

N. Riverpod Provider dan FutureProvider.family

lib/state/agenda_providers.dart
final agendaRepositoryProvider = Provider<AgendaRepository>(
  (ref) => AgendaRepository(),
);

final agendaDetailProvider = FutureProvider.family<Agenda, String>(
  (ref, id) => ref.watch(agendaRepositoryProvider).findById(id),
);

family berarti provider menerima parameter. agendaDetailProvider('a1') dan agendaDetailProvider('a2') adalah dependency berbeda. Alur UI: Provider → Future → AsyncValue → loading/success/error.

N.1 Retry

Retry harus mengulang request: ERROR → RETRY → LOADING → SUCCESS/EMPTY/ERROR. Pada provider, gunakan invalidate atau panggil ulang notifier sesuai pola yang dipakai.

S. Debugging Lab

  1. ProviderScope missing: pastikan root memakai ProviderScope.
  2. No GoRouter found: pastikan memakai MaterialApp.router dan router yang benar.
  3. Route tidak ditemukan: bedakan /agenda/:id dengan /agenda/id.
  4. Detail selalu sama: periksa id dan gunakan provider family.
  5. Retry tidak bekerja: pastikan alurnya error → retry → request ulang.
