Navigasi dan Pengelolaan State

Membuat alur daftar–detail untuk layanan kegiatan mahasiswa dan menangani state loading, error, serta berhasil secara terukur.

A. Identitas Praktikum

Pertemuan: 3 · Prasyarat: Modul 01–02, konsep class dan widget.

B. Capaian Pembelajaran

  • Mahasiswa mampu membedakan navigasi berbasis stack dan router deklaratif.
  • Mahasiswa mampu menerapkan route daftar dan detail menggunakan GoRouter.
  • Mahasiswa mampu menjelaskan alasan penggunaan state management pada aplikasi yang bertumbuh.
  • Mahasiswa mampu memodelkan state loading, error, dan success.

C. Konsep Dasar

Navigator mengelola route seperti stack. push menambah halaman, sedangkan pop kembali ke halaman sebelumnya. Router deklaratif seperti GoRouter memusatkan definisi path dan memudahkan deep link. State management membantu memisahkan data yang berubah dari widget presentasi.

StateTampilan
LoadingIndikator proses dan pesan singkat
ErrorPesan yang dapat ditindaklanjuti dan tombol coba lagi
SuccessDaftar atau detail data

D. Studi Kasus

Pada aplikasi UNIMUGO Event, mahasiswa memilih agenda dari daftar dan membuka halaman detail. Data awal masih berasal dari repository lokal, tetapi struktur state dibuat agar pada modul berikutnya dapat diganti dengan REST API tanpa mengubah seluruh UI.

E. Langkah Praktikum

Langkah 1 — Tambahkan dependency

flutter pub add go_router
flutter pub add flutter_riverpod

Langkah 2 — Definisikan route

final router = GoRouter(
  routes: [
    GoRoute(path: '/', builder: (_, __) => const AgendaPage()),
    GoRoute(
      path: '/agenda/:id',
      builder: (_, state) => DetailPage(
        id: state.pathParameters['id']!,
      ),
    ),
  ],
);

Gunakan MaterialApp.router(routerConfig: router). Parameter :id memungkinkan satu halaman detail digunakan untuk banyak agenda.

Langkah 3 — Pisahkan state dari tampilan

Buat provider atau notifier yang mengekspos state dengan tiga keadaan. Widget hanya membaca state dan memilih tampilan yang sesuai. Jangan mencampur pemanggilan data, navigasi, dan seluruh markup dalam satu method build.

Langkah 4 — Uji alur

  1. Buka daftar agenda.
  2. Pilih agenda “Workshop Git untuk Proyek TI”.
  3. Pastikan detail menampilkan id yang benar.
  4. Simulasikan error repository dan pastikan tombol “Coba lagi” dapat digunakan.

F. Hasil yang Diharapkan

  • Route / dan /agenda/:id dapat dibuka.
  • Tombol kembali mengembalikan pengguna ke daftar.
  • UI memiliki keadaan loading, error, dan success.
  • Data dan widget dipisahkan dalam folder yang masuk akal.

G. Eksperimen

Tambahkan route /agenda/:id/daftar-hadir dan buat guard sederhana: halaman hanya dapat dibuka jika id agenda tidak kosong. Uji deep link dengan menempelkan URL detail pada browser/emulator web.

H. Tugas Praktikum

Bangun fitur pencarian agenda. Search bar harus mengubah daftar berdasarkan judul, memiliki keadaan hasil kosong, dan tetap mempertahankan navigasi ke detail. Sertakan satu widget test untuk memastikan item hasil pencarian tampil.
